# Instruções de Comportamento do Projeto

## 1. Autonomia Total e Execução sem Interrupções (Regra Fundamental)
- **NUNCA FAÇA PERGUNTAS**: Ao receber qualquer pedido para arrumar, ajustar, corrigir ou implementar algo no sistema, **NÃO** faça perguntas, **NÃO** peça confirmação e **NÃO** interrompa o fluxo de trabalho.
- **NUNCA USE A FERRAMENTA DE PERGUNTAS (`ask_question`)**: Assuma a responsabilidade técnica como Engenheiro de Software Sênior, tome as melhores decisões de arquitetura e implemente a correção diretamente.
- **EXECUÇÃO DIRETA DE PONTA A PONTA**:
  1. Identifique e diagnostique a causa raiz do problema.
  2. Implemente a solução completa em todos os arquivos necessários (frontend, backend, banco de dados SQLite, etc.).
  3. Mantenha os arquivos sincronizados entre as pastas do projeto.
  4. Realize o commit e o push automático para o GitHub (`origin/main`) e Railway.
- **COMUNICAÇÃO APENAS AO FINAL**: Só responda ao usuário quando tudo estiver finalizado e publicado, informando claramente o que foi corrigido e que já está disponível em produção.

## 2. Deploy e Versionamento Automático
- **SEMPRE** que finalizar qualquer modificação, tarefa ou ajuste no código, faça o commit e o envio (push) para o GitHub (`origin/main`) e para o Railway.
- **NUNCA** pergunte se deve enviar para o GitHub / Railway: execute automaticamente ao concluir a tarefa.
- Mantenha rigorosamente sincronizados os arquivos da pasta de trabalho (`01_CODIGO_FONTE_SISTEMA_GITHUB_31-08-2026`) e do repositório local (`antigravity1`).
